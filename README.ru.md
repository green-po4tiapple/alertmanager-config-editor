# Редактор дерева роутинга Alertmanager

Редактор дерева роутинга Prometheus Alertmanager, работающий целиком в браузере.
Вставляете `alertmanager.yml` — или только блок `route:`, или HelmRelease, внутри
которого он лежит, — читаете дерево, правите его, проверяете, в какие receiver'ы
реально уедет алерт, и забираете YAML обратно.

**[Живое демо →](https://green-po4tiapple.github.io/alertmanager-config-editor/?demo=1)**
· [English README](README.md)

Без бэкенда, без сборки на стороне пользователя, конфиг наружу не уходит.

> По сути это официальный
> [routing-tree-editor](https://prometheus.io/webtools/alerting/routing-tree-editor/)
> плюс редактирование, точная семантика `continue`, экспорт YAML и пакетная
> проверка, которая показывает, какие ваши алерты теряются молча.

![Блочный режим с проверкой алерта](docs/img/block-view.png)

## Зачем

Роутинг Alertmanager детерминирован, но читается неверно на удивление легко, а
ломается молча. Самый дорогой случай:

```yaml
- matchers:
    - team="payments"
  routes:
    - receiver: payments_pager
      matchers: [severity="critical"]
    - receiver: payments_chat
      matchers: [severity="warning"]
```

Алерт с `team=payments, severity=info` попадает в родительскую ветку, не совпадает
ни с одним ребёнком, а своего `receiver`'а у родителя нет — потому что **receiver
не наследуется от родителя**. Алерт исчезает. Ни ошибки, ни строчки в логе, ни
единого следа на дашборде.

Редактор помечает такие ветки бейджем, а пакетный режим считает, сколько ваших
настоящих алертов в них проваливается.

## Что умеет

| | |
|---|---|
| **Два режима над одним деревом** | Вложенный список карточек с инлайн-правкой и диаграмма. Модель одна, переключение свободное. |
| **Две раскладки графа** | **Радиальная** — как в официальном routing-tree-editor. **Блоки** — org-chart сверху вниз с матчерами внутри узлов и drag&drop переподвешиванием. |
| **Правка структуры** | Перемещение среди соседей, вложить/поднять, добавить дочернюю или соседнюю, удалить, перетащить ветку на нового родителя. |
| **Проверка алерта** | Произвольные пары `label=value` → все receiver'ы, куда уедет алерт, с исходом каждого: доставлено / дроп (явный null) / дроп (нет receiver'а). Путь подсвечивается в обоих режимах. |
| **Пакетная проверка** | Прогон целой выгрузки алертов по дереву: «алерт → receiver → почему», со счётчиком **потеряно**. См. [`docs/BATCH-CHECK.md`](docs/BATCH-CHECK.md). |
| **Регрессия роутинга** | После правки каждая строка считается ещё и по дереву на момент загрузки: видно «переадресовано 65 алертов из 332», а не «изменилось 4 строки YAML». |
| **Поиск** | По имени receiver'а или тексту матчера, с переходом к ветке в любом режиме. |
| **Дифф перед экспортом** | Построчное сравнение с деревом на момент загрузки, без шума нормализации YAML. |
| **Undo/Redo** | `⌘/Ctrl+Z` и `⌘/Ctrl+Shift+Z`. Один снэпшот на сессию редактирования поля, а не на каждый символ. |
| **Экспорт** | `⌘/Ctrl+E`: готовый блок `route:` либо исходный файл с заменённым только этим блоком. |
| **Загрузка из живого Alertmanager** | `GET /api/v2/status` → `config.original`, вставлять руками ничего не нужно. |
| **Темы и языки** | Светлая/тёмная по системной настройке плюс ручной переключатель. Интерфейс на английском и русском. |

## Быстрый старт

```bash
npm ci
npm run dev        # http://127.0.0.1:5180
```

Остальные команды:

```bash
npm test           # юнит-тесты ядра (vitest)
npm run typecheck  # tsc --noEmit
npm run build      # прод-сборка в dist/
npm run preview    # посмотреть прод-сборку локально
```

Больше ничего не требуется: откройте страницу, нажмите **Пример**, чтобы загрузить
демонстрационный конфиг, либо вставьте свой.

## Модель безопасности

Этот раздел стоит прочитать до того, как вставлять боевой конфиг.

- **Конфиг не покидает страницу.** Разбор, правка и экспорт происходят в браузере.
  Само по себе приложение никуда не ходит.
- **Наружу уходят только те запросы, которые вы запустили**, и только на адреса,
  которые вы ввели сами: загрузка конфига из Alertmanager, выгрузка правил и
  горящих алертов и — если включите — обогащение лейблов из
  Prometheus/VictoriaMetrics. В этих запросах едут пути API и выражения правил.
  **Дерево роутинга и вставленный конфиг не отправляются никогда.** Куки не
  передаются (`credentials: 'omit'`).
- **Ничего не сохраняется.** Конфиг живёт только в памяти вкладки: ни
  `localStorage`, ни `sessionStorage`. Перезагрузка страницы даёт чистый экран
  вставки. Единственное исключение — выбранный язык интерфейса.
- **Из `receivers:` читаются только имена.** Токены, URL и `*_configs` в состояние
  приложения не попадают вообще, включая sops-шифртексты в HelmRelease. На это есть
  тест.
- **Экспорт «весь файл» — текстовая подстановка**, а не пересборка YAML, поэтому
  секреты и комментарии исходного файла переносятся символ в символ.

## Self-hosting через Docker

Полезно, когда нужно поднять редактор рядом со своим Alertmanager: страница по
обычному HTTP может обращаться к `http://`-адресам, которые браузер со
HTTPS-страницы блокирует как mixed content.

```bash
docker build -t alertmanager-config-editor .
docker run --rm -p 8080:8080 alertmanager-config-editor   # http://localhost:8080
```

Образ — `nginx-unprivileged` (~76 МБ, слушает 8080, root не нужен), есть `/healthz`.
Работает с read-only корневой файловой системой, если дать два tmpfs:

```bash
docker run --rm --read-only --user 101:101 --cap-drop ALL \
  --tmpfs /tmp --tmpfs /var/cache/nginx -p 8080:8080 alertmanager-config-editor
```

## Проверка экспорта

`npm test` кладёт в `amtool-out/` готовые конфиги Alertmanager, собранные
сериализатором этого проекта. Дальше CI проверяет их **настоящим** бинарём
Alertmanager. Локально то же самое:

```bash
npm test
docker run --rm -v "$PWD/amtool-out:/cfg" --entrypoint sh \
  prom/alertmanager:v0.28.1 -c 'amtool check-config /cfg/*.yaml'
```

Можно прогнать всё ядро по своему конфигу — без переменной тест пропускается:

```bash
AM_CONFIG=/path/to/alertmanager.yml npm test
```
